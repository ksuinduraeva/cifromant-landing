# Цифромант — Лендинг

Сайт нумерологического Telegram-бота **Цифромант**. Основная задача — SEO-трафик через статьи про нумерологию и конвертация в подписчиков бота.

**Публичное название:** Цифромант
**Слоган:** Цифромант — когда цифры становятся подсказками
**Сайт:** cifromant.ru
**Бот в Telegram:** @number_day_bot

## Продукт: что, зачем и для кого

**Что мы делаем:**
Цифромант — нумерологический инструмент на базе AI. Рассчитывает персональные числа по дате рождения и имени, генерирует уникальный прогноз на день/месяц/год и анализирует совместимость пар. Каждый прогноз написан именно для этого человека — с его числами, его характером, его текущим периодом.

**Зачем мы это делаем:**
Люди хотят понимать себя и происходящее вокруг. Нумерология даёт простой и доступный язык для этого. Мы убираем мистику и пафос — и делаем из нумерологии практичный инструмент самопознания, который работает каждый день.

**Для кого:**
- Преимущественно женщины 25–60 лет
- Интересуются нумерологией, астрологией, психологией, саморазвитием
- Хотят понимать себя и отношения глубже
- Ценят персонализацию — «специально для меня», а не «общий гороскоп»
- Открыты к практикам и рефлексии, но не хотят тяжёлой эзотерики
- Готовы платить за качественный ежедневный инструмент (29–299 ₽/месяц)

**Ключевое отличие от конкурентов:**
Не шаблонный гороскоп для всех — а прогноз, который учитывает уникальное сочетание чисел конкретного человека. Пользователь чувствует, что текст написан именно про него.

**Роль лендинга:**
Привлечь человека через поиск (он ищет «число жизненного пути» или «совместимость по числам») → дать ценную статью → познакомить с Цифромантом → отправить в бота.

## Стек лендинга

- **Next.js 16** (App Router) — фреймворк, **статический экспорт** (`output: 'export'`) для SEO
- **TypeScript** — типизация
- **Tailwind CSS** — стили
- **Markdown-файлы** — статьи (`content/articles/*.md`), без CMS
- **Хостинг:** **Timeweb** (российский, без VPN), HTTPS/Let's Encrypt. Автодеплой: GitHub Actions собирает `out/` и заливает по **FTP** на Timeweb (`.github/workflows/deploy.yml`, сервер `vh464.timeweb.ru` → `/public_html/`; пароль — секрет `FTP_PASSWORD`). Vercel отключён.
  - ⚠️ FTP-шаг может **молча упасть** (напр. если слетел пароль). После пуша проверять «200 на проде» (`curl -I https://cifromant.ru`), при сомнении — статус в GitHub → Actions.

> **Почему ушли с Vercel и Sanity:**
> - Vercel и Cloudflare замедляются/блокируются РКН → российские юзеры не открывали сайт без VPN. Поскольку весь смысл лендинга — РФ-трафик из Яндекса, переезжаем на российский хостинг.
> - Sanity (CMS) был избыточен: статьи всё равно пишутся в Claude Code и коммитятся в репозиторий, веб-редактор не нужен. Убрав Sanity, сайт стал полностью статическим → его можно положить на любой дешёвый хостинг.

## Как добавить статью

1. Создать файл `content/articles/<slug>.md`. Имя файла = URL статьи.
2. Frontmatter (строковые значения **обязательно в кавычках** — иначе двоеточие в тексте ломает YAML):
   ```
   ---
   title: "Заголовок статьи"
   description: "Краткое описание для SEO."
   publishedAt: "2026-06-03"
   ---
   ```
3. Дальше — текст статьи в Markdown (`## подзаголовки`, `**жирный**`, списки).
4. Запушить в `main` → GitHub Actions соберёт и зальёт на Timeweb.

**Причины, по убыванию важности:**
1. **Нет внешних сигналов вообще.** На сайт не ссылается никто, соцсетей нет, трафика нет → для Яндекса он «остров, на который никто не плывёт». 2. **Нет canonical** — Яндекс говорит прямым текстом. Не убийца сам по себе, но лишний повод счесть страницу неоднозначной (тем более при `/articles/x` → 301 → `/articles/x/`).

### Фаза 15 — Переезд бота на российскую инфраструктуру *(бот; ОТЛОЖЕНО — вернуться после текущего плана)*

**Две независимые причины, почему это придётся сделать:**
1. **Закон (152-ФЗ, локализация ПДн).** Персональные данные россиян — дата рождения, имя, ФИО — должны **первично записываться** на серверах в РФ. 2. **Блокировки.** Railway и Supabase могут замедлить или отрезать — ровно то, что уже случилось с Vercel и заставило переезжать лендинг. Тогда бот просто перестанет работать.

#### ⚠️ Главная ловушка: OpenAI не обслуживает Россию

Здесь два РАЗНЫХ блокирующих механизма, их нельзя путать:
- **РКН блокирует «оттуда сюда»** — из-за этого лендинг не открывался на Vercel. Решено переездом на Timeweb.
- **OpenAI блокирует «отсюда туда»** — он сам не принимает запросы с российских IP (`403 unsupported_country_region_territory`), независимо от того, оплачен ключ или нет.

Сейчас бот на Railway → запрос уходит с зарубежного IP → всё работает. **В день, когда бот встанет на российский сервер, генерация сломается сразу** — прогнозы, месяц, год, совместимость. Не «замедлится», а перестанет работать. Значит, прослойку надо готовить **до** переезда сервера.

**Варианты прослойки:**
- **Свой прокси на зарубежном VPS** (~$5/мес). Ключ и данные остаются у нас. Минус: ещё одна точка отказа, поддерживать самим (есть смежная отложенная задача — VPS под прокси для Telegram, можно совместить).
- **Российский реселлер OpenAI API** (ProxyAPI, VseGPT и т.п.) — совместимый endpoint, оплата рублями, канал держат они. Минус: наши промпты (имя, дата рождения, числа) идут через чужую компанию → отразить в политике ПДн + зависимость от их надёжности и наценки.
- **Российская модель** (YandexGPT / GigaChat) — канал внутри РФ, юридически чище всего. ⚠️ Минус серьёзный: **качество текста прогноза и есть продукт**. Тон вылизывали месяцами → смена модели = переписать промпты и заново проверять живыми генерациями. Не «поменять строчку».
- **Гибрид (предпочтительно):** OpenAI через свой прокси + российская модель как запасной путь, чтобы утренняя рассылка не срывалась.
